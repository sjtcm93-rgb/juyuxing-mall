# 退款只读查询与错误留存实施计划

**Goal:** 不再次申请退款即可查询渠道状态，并让后台错误详情持续可见、可复制。

**Architecture:** `admin.queryRefundStatus` 在店主/财务鉴权后读取退款、订单及商户配置，只调用 `cloudPay.queryRefund`，不写数据库。后台为每笔退款保留本次页面会话的诊断结果，查询不等于退款或账务同步。

**Tech Stack:** JavaScript、CloudBase、Vue 3、Node VM 隔离测试。

## 执行

1. 新建 `scripts/refund-diagnostics-test.js`，模拟只读数据库（所有写入抛错）和微信渠道，先验证缺失接口失败。
2. 新建 `cloudfunctions/admin/refund-query.js`，增加权限受控的 `queryRefundStatus` 分支，校验本地记录与渠道退款单号，白名单返回；未查到、异常和格式不完整不能解释为可再次退款。
3. 在 `admin-web/app.js` 和 `admin-web/index.html` 增加只读查询、持续错误卡片、复制诊断信息。按钮互斥，异常时释放 loading；详情模式不能提交退款。
4. 测试实际后台 setup 方法及云函数入口：权限、成功/处理中/未查到/错误、零资金调用、零写库、重复点击、错误留存和复制。
5. 将查询权限与零写入断言加入 `scripts/e2e-mock.js`，更新 smoke，运行所有本地门禁。

## 接口依据与边界

- [微信支付合作伙伴 V2 查询退款文档](https://pay.wechatpay.cn/doc/v2/partner/4011984212)：按退款单号查询、业务结果与退款状态分开判断、编号字段白名单解析。
- `wx-server-sdk` 本地实现负责驼峰/下划线转换。查询使用现有 CloudPay 通道，不引入或索取商户私钥。
- 不部署、不修改环境超时、不启用付费日志、不重试真实退款。旧提示无法恢复，新错误在本次后台页面会话中保留（刷新页面会清空）。

## 部署交接

- 完整部署 `cloudfunctions/admin/`（必须带上新增 `refund-query.js`），然后刷新后台。只更新网页而不更新云函数会显示“云端尚未部署退款查询接口”，不会降级为发起退款。
- 在退款列表或详情中点“查询微信退款（只读）”。仅店主、财务可调用；运营和消费者被服务端拒绝。
- 查询成功也不会同步本地账务；尤其“微信已退款成功 / 本地待处理”须另行核对处理，不能再点退款。
- 旧页面已消失的错误无法恢复。本功能帮助安全核查渠道现状，不代表已经确认或修复先前那笔真实退款失败的根因。
